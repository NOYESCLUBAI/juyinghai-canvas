# 漫金海公开上线检查清单

规划文档，不含实现。调研日期：2026-10-18。

本文回答：现在的漫金海是本机应用，要变成任何人都能打开的网站，代码和运营上还缺什么。合规条目列出需要负责人自行向律师或主管部门确认的问题，并附当日能打开的官方文本。本文不是法律意见，不判断漫金海是否已经满足某一备案或许可。

## 结论

今天的网站形态不存在。浏览器把项目写在 `localStorage`，把图片和视频写在 IndexedDB；可选的 Supabase 邮箱登录只改变这些键的前缀，不上传任何内容。FastAPI 只监听 `127.0.0.1`，全站共用一份 `.local/model-configs.json`，生成接口不校验登录。`docs/open-source-release.md` 已写明：不要把本机后端改成公网监听来充当在线版。

建议两期：

| 阶段 | 对用户可见的结果 | 规模 |
| --- | --- | --- |
| 第一期，邀请内测 | 受邀账号可在另一台设备打开自己的项目和素材；模型密钥按用户保管（BYOK）；前后端部署在公网域名上，未登录不能调用生成 | 新的账号鉴权、项目 API、对象存储和视频任务，触及存储与全部 `/api` 路由。大于 Agent 路线图的 P0 |
| 第二期，公开注册 | 在负责人确认适用的备案、标识和协议完成之后开放注册；平台额度或计费、内容标识、监控、引导和落地页 | 合规手续与计费、审核并行。计费和审核是新子系统；标识和文案小于第一期的存储改造 |

本地开源用法保留：不配置 Supabase、不部署时，现有本机画布和 `.mjh.json` 备份继续可用。

## 1. 账号与云端持久化

### 1.1 现在的登录做了什么

`src/auth/client.ts` 只在同时存在 `VITE_SUPABASE_URL` 和 `VITE_SUPABASE_PUBLISHABLE_KEY` 时创建客户端。认证为 PKCE，会话留在浏览器，自动刷新。`.env.example` 标明这两个变量是前端公开配置，禁止把服务端密钥放进 `VITE_`。

`src/auth/AuthProvider.tsx` 提供邮箱注册、密码登录、找回密码、重置密码、昵称和六个动物头像。注册后提示查收验证邮件。个人中心文案写明：「按账号分别保存在当前浏览器，暂未开启跨设备同步。」退出使用 `signOut({ scope: 'local' })`，只清本机会话。未配置 Supabase 时，对话框显示「登录服务尚未配置」，用户仍可「继续使用本机画布」。

`src/auth/accountStorage.ts` 的隔离方式是键前缀：登录后 `mjh.projects.v1` 变成 `mjh.account.${userId}.mjh.projects.v1`。`tests/accountStorage.test.ts` 只验证同一浏览器里访客数据与两个账号互不覆盖。没有服务端访问控制。

`src/auth/importLocalLibrary.ts` 把未登录时的 `localStorage` 项目，以及 IndexedDB `manjinhai-canvas-media` / 旧名 `manlinghai-canvas-media` 里的 `media`、`projectAssets`、`globalAssets`，复制到 `manjinhai-canvas-media-${userId}`。原件保留，并用 `mjh.account.${userId}.local-imported` 防止再导一次。这是本机复制，不是云同步。换一台电脑登录同一邮箱，项目不会出现。

### 1.2 项目与素材实际存在哪里

| 数据 | 位置 | 代码 |
| --- | --- | --- |
| 项目库 | `localStorage` 键 `mjh.projects.v1`，结构 `{ version: 1, projects, lastOpenedProjectId }` | `src/projects/projectStore.ts` |
| 单个项目 | `SavedProject` version 2：标题、分集、节点、边、视口。节点上的 `assetUrl` 写入前被去掉，只留 `assetId` | `cleanProject` |
| 媒体字节 | IndexedDB `manjinhai-canvas-media`（登录后加账号后缀），库版本 2，对象库 `media` / `projectAssets` / `globalAssets` | `src/lib/mediaStore.ts` |
| 模型选择 | `mjh.model-selections.v2`，只存所选配置 id，不存密钥 | `src/lib/modelConfigs.ts` |
| 路由 | 哈希 `#/projects`、`#/project/:id` | `src/projects/ProjectManager.tsx` |

README 写明：清除站点数据或换设备后不会自动同步。公开站若继续用这套存储，账号没有云端数据可言。

### 1.3 要补上的云端形状

第一期至少把「谁拥有这份项目」从键前缀改成数据库行上的 `user_id`。建议：

- 项目正文继续用现有 JSON（version 2），整份或按分集存。画布结构先不要为了上线改成另一种文档模型。
- 媒体放对象存储，键包含 `user_id` 和 `assetId`。浏览器只拿短期签名 URL。`readMedia` / `saveMedia` 的调用点改成上传和签名，而不是把 Blob 留在 IndexedDB。
- 项目资产、全局资产沿用现有登记字段（`projectId`、`assetId`、`kind`、`fileName`、`createdAt`）。全局资产不属于单个项目，备份格式里也没有它们，云端要单独一张表。
- 封面 `coverAssetId` 指向同一套对象。
- 删除媒体时沿用 `deleteMedia` 的规则：项目历史或全局收藏仍引用该 `assetId` 时不删对象。

Supabase 已经在依赖里（`@supabase/supabase-js` 2.109.0，见 `package.json` 与 `THIRD_PARTY_NOTICES.md`），Auth 可继续用。Postgres 和 Storage 可以用同一个 Supabase 项目，也可以换成别的数据库加对象存储。无论选哪边，FastAPI 都要验证用户 JWT，不能只靠浏览器里的 `setAccountScope`。行级权限如果做在数据库上，要和 FastAPI 的 `user_id` 过滤一致，避免两条路有一条没校验。

### 1.4 把已有本机作品迁上去

两条入口都要保留，并且都做成「新副本」，不覆盖云端已有项目。这和今天的导入语义一致。

1. **已登录浏览器里的本机库。** 现有「导入原有本机内容」按钮（`AuthProvider.tsx` 个人中心）只调用 `importLocalLibrary`。公开站应在此之后再上传：读账号前缀下的项目库和 IndexedDB，逐个媒体上传，写云端项目，成功后保留本机原件。大视频要分块，失败的项目保持未导入，已上传的对象可清理。`local-imported` 标记不能再表示「云端已完成」。
2. **`.mjh.json` 备份。** `src/projects/projectBackup.ts` 的格式是 `{ format: 'manjinhai-project', version: 1, entry, media }`。`parseBackup` 校验分集、节点类型（`text` / `image` / `video`）、边和媒体类型（png、jpeg、webp、gif、avif、mp4、webm、quicktime）。单文件上限 `BACKUP_LIMIT` 为 100 MB，超出时提示先单独下载大型视频。媒体是 base64。README 写明备份不含账号、模型密钥、Agent 对话和全局资产收藏状态。

云端导入应复用 `parseBackup` 的规则，把 base64 写成对象存储，并像 `importProject` 那样换新的项目 id 和 assetId，标题加「（导入）」。100 MB 的 JSON 不适合一次塞进无限制的请求体；第一期要么维持 100 MB 并调高该路由的体限制，要么改成先传媒体、再传不含 base64 的项目描述。后一种才能超过今天的视频备份上限。

未登录的本机模式继续写 `localStorage` 和 IndexedDB。登录后的公开站以云端为准，避免同一账号在两台设备上各改一份本地库。

## 2. 模型密钥与费用

### 2.1 现在密钥在哪

浏览器不保存模型密钥。`backend/model_configs.py` 的 `public()` 去掉 `api_key`，只返回 `configured`。自定义配置和共享 Agnes 连接写在 `PROJECT_ROOT / '.local' / 'model-configs.json'`（`backend/app.py` 的 `ConfigStore`）。写入用临时文件再 `os.replace`，临时文件由 `mkstemp` 创建。目录权限 `0o700`。环境变量仍可用：`.env.example` 中的 `MJH_LLM_API_KEY`、`MJH_IMAGE_API_KEY`、`MJH_VIDEO_API_KEY`，以及对应的 base URL 和模型名。`request_settings` 在请求开始时读取配置，之后改文件不影响进行中的那一次调用。

生成接口接受 `model_config_id`。这个 id 在全进程唯一，没有 `user_id`。`/api/health` 会返回默认模型名和是否已配置密钥。

README 写明：不附带共享额度，使用者填写自己的地址、Key 和模型 ID。

### 2.2 第一期用 BYOK

公开内测沿用「用户自己的 Key」，不把仓库里的一份 Agnes Key 变成所有访客的额度。

- 每个用户自己的配置行：名称、类型、协议、base URL、模型 id、加密后的密钥。加密密钥放在服务端密钥管理里，不进镜像、不进日志。
- 列表接口继续只返回 `configured`，不回显密钥。更新时允许留空表示保留旧密钥，与今天 `ConfigStore.save` 的行为相同。
- 校验 URL 继续用 `normalize_url`：只要 http(s)、拒绝把账号密码写进 URL。
- 测试连接 `POST /api/model-configs/{id}/test` 必须限定为当前用户的配置。
- 环境变量里的 Key 只作为运营者本机或未登录本地模式的默认值，不作为公开站的回退。否则一个未带 `model_config_id` 的请求会花到平台 Key 上。`modelRequest` 在没有配置 id 时仍会退回 `{ model }`（`src/lib/modelConfigs.ts`），服务端必须拒绝这种公开请求。

### 2.3 滥用与以后的平台额度

BYOK 不能代替限流。攻击者可以用自己的 Key 打满进程，或用他人账号反复创建视频任务。第一期按用户和 IP 限制：文字、图片、视频分开计数；视频并发数要小于工作进程能同时挂住的请求数（见第 3 节）。登录、注册沿用 Supabase 已映射的 `over_email_send_rate_limit` 和 `over_request_rate_limit`（`src/auth/client.ts`），这只保护邮件，不保护 `/api/images/generate`。

第二期若改为平台代付或积分：

- 额度记在用户行上，在调用上游之前扣减或预留，失败则退回。当前标价可能为 0，不能把「现在免费」写成无限额。
- 账单、发票和退款是另一套流程，第一期不做。
- 平台 Key 与用户 BYOK 可以并存，但每次请求只能命中其中一种，并在任务记录里记下用的是哪一种。

## 3. 后端多租户

### 3.1 现在没有租户

`package.json` 与 `scripts/dev.sh` 都把 uvicorn 绑在 `127.0.0.1`。`LOCAL_ORIGINS` 只放本机 Vite 端口。`CORSMiddleware` 使用这份列表。`protect_local_config` 用 `Origin` 头拒绝非本机对 `/api/model-configs` 的访问。非浏览器客户端可以不带 `Origin`。生成、对话和健康检查没有这条检查，也没有登录。

因此公开部署若只改监听地址，任何人都能读改模型配置、用服务器上的 Key 生图生视频。这是上线前必须改掉的行为，不是优化项。

依赖只有 FastAPI、httpx、python-dotenv、uvicorn（`requirements.txt`）。没有用户表、队列或对象存储客户端。

### 3.2 接口要按用户重做

| 现接口 | 现行为 | 公开站 |
| --- | --- | --- |
| `POST /api/chat` | `call_agnes`，`stream: false`，返回整段文字 | 校验 JWT，使用该用户的文字配置 |
| `POST /api/images/generate` | `generated_images_from_response` 把图片收成 data URL，JSON 一次返回 | 同样校验；大图改为对象存储地址，避免响应体把 base64 再传一遍 |
| `POST /api/videos/generate` | `call_video_model` 在这个请求里创建任务、每 3 秒轮询，直到 `MJH_VIDEO_TIMEOUT_SECONDS`（示例为 420）或失败，然后下载整段 MP4，以 `Content-Disposition: inline` 返回字节 | 改为入队。请求立即返回任务 id。工作进程轮询 Agnes，结果写入对象存储。客户端再保存到自己的素材 |
| `GET/POST/PUT/DELETE /api/model-configs` | 读写本机一份 JSON | 按 `user_id` 读写，密钥加密 |
| `GET /api/health` | 返回是否已配置密钥和模型名 | 公开站只返回进程存活。模型是否配好放到已登录的目录接口 |

前端全部使用相对路径 `fetch("/api/...")`（`src/lib/textWriter.ts`、`imageWriter.ts`、`videoWriter.ts`、`modelConfigs.ts`、`src/agent/canvasAgent.ts`）。开发时由 `vite.config.ts` 代理到 `MJH_CANVAS_API_TARGET`。生产构建没有这个代理，也没有 API 基址变量。部署时要么由同一域名反代 `/api`，要么增加明确的 API 基址并让上述调用点走它。密钥仍不得出现在前端。

### 3.3 视频任务

`call_video_model` 在持有 httpx 客户端的同时睡到视频完成，再把 `download_response.content` 放进内存。一个 uvicorn worker 上挂住数分钟的请求，内测里少数并发就会占满。公开站应：

- 任务表：`user_id`、状态、上游 `video_id`、错误、结果对象键、创建时间。
- 独立 worker 轮询，间隔可以沿用现在的 3 秒，超时沿用配置里的秒数。
- 进程重启后能从 `video_id` 接着查，而不是再创建一次上游任务。
- 结果对象写入该用户的前缀；接口只对本人签发读取 URL。
- 用户停止时标记取消。已经在上游创建的任务未必能撤回，界面要说明「已提交的视频可能仍会计费」。

图片路径今天已经把上游字节收成 data URL（`image_data_url`）。公开站同样应落对象存储。画布节点继续只存 `assetId`。

## 5. 面向境内用户时的合规，以及 AGPL

本节只列出公开文本里的义务类型，方便负责人拿去确认「做不做、谁来做、何时做完」。是否适用取决于服务器所在地、运营主体、是否向境内公众提供、是否收费、生成能力由谁提供。这些事实本文不代替确认。

### 5.1 网站备案与电信业务

- 《非经营性互联网信息服务备案管理办法》（信息产业部令第 33 号，2024 年 1 月 18 日工业和信息化部令第 68 号修订）规定，在境内提供非经营性互联网信息服务应当备案；未经备案不得提供。备案编号放在网站首页底部并链接备案管理系统。文本：<https://www.miit.gov.cn/gyhxxhb/jgsj/cyzcyfgs/bmgz/xxtxl/art/2024/art_84a0cfa0ebd049bbbe751dca9a008e56.html>。查询与办理入口见工业和信息化部备案系统 <https://beian.miit.gov.cn>。
- 工信部办事页把「有偿提供信息」列为经营性，并说明经营性网站在备案之外还要办理增值电信业务许可：<https://jxca.miit.gov.cn/bsfw/bszn/cjwt/art/2020/art_869445de6a9f40e98732195df440f99d.html>。第二期若向用户收费，要单独确认是否构成经营性互联网信息服务以及需要哪一类许可证。
- 服务器不在境内、但向境内公众提供服务，是否仍要备案或会被要求处置，不能从「服务器在国外」直接推出结论。生成式人工智能办法第二十条写的是：来源于境外、向境内提供且不符合规定的服务，国家网信部门可以通知机构采取技术措施。见 <https://www.gov.cn/zhengce/zhengceku/202307/content_6891752.htm>。

邀请内测只要在境内对他人提供可访问的网站，负责人就应确认备案是否已经适用，不要把「尚未公开注册」当成免除备案的依据。本文不替这个判断下结论。

### 5.2 生成式人工智能、深度合成与标识

漫金海的在线版会向用户返回文字、图片和视频。产品自己不训练模型，调用的是用户或平台配置的上游。办法第二十二条把「提供者」定义为利用生成式人工智能技术提供服务的组织或个人，并包括通过可编程接口提供服务的情形；「使用者」是使用该服务生成内容的组织或个人。漫金海站在哪一边，由负责人根据是否由本站向公众提供生成能力来确认。

需要对照的文本：

- 《生成式人工智能服务管理暂行办法》（国家网信办等七部门令第 15 号，2023 年 8 月 15 日起施行）。第二条：向境内公众提供生成文本、图片、音频、视频等内容的服务适用；未向境内公众提供的研发、应用不适用。第九条：提供者承担网络信息内容生产者责任；涉及个人信息的，承担个人信息处理者责任。第十一条：保护使用者输入信息和使用记录，不得非法留存可识别身份的输入和使用记录。第十二条：按深度合成规定对图片、视频等标识。第十四条：发现违法内容要停止生成、停止传输、消除并报告。第十五条：投诉举报入口。第十七条：具有舆论属性或社会动员能力的，要做安全评估，并按算法推荐规定备案。第二十三条：法律、行政法规要求许可的，依法取得。全文：<https://www.gov.cn/zhengce/zhengceku/202307/content_6891752.htm>。
- 《互联网信息服务深度合成管理规定》（国家网信办、工信部、公安部令第 12 号，2023 年 1 月 10 日起施行）。第十七条列出可能导致公众混淆的服务（含智能对话、智能写作、人脸与人物图像视频等）的显著标识。第十九条：具有舆论属性或社会动员能力的深度合成服务提供者，以及技术支持者，履行算法备案，并在站点显著位置标明备案编号。全文：<https://www.gov.cn/zhengce/zhengceku/2022-12/12/content_5731431.htm>。
- 《互联网信息服务算法推荐管理规定》（2022 年 3 月 1 日起施行）第二条把生成合成类列入算法推荐技术。第二十四条：具有舆论属性或社会动员能力的，在提供服务之日起十个工作日内通过算法备案系统填报。备案系统：<https://beian.cac.gov.cn>。规定全文：<https://www.gov.cn/zhengce/2022-01/04/content_5728941.htm>。系统上线通告：<https://www.cac.gov.cn/2022-02/25/c_1647395666889023.htm>。
- 《人工智能生成合成内容标识办法》（国信办通字〔2025〕2 号，2025 年 9 月 1 日起施行）。显式标识：文本提示、图片显著标识、视频起始画面和播放周边标识；提供下载、复制、导出时文件中仍要有符合要求的显式标识。隐式标识写入文件元数据，包含生成合成属性、服务提供者名称或编码、内容编号等。用户协议要写明标识方法和样式。全文：<https://www.gov.cn/zhengce/zhengceku/202503/content_7014286.htm>。配套强制性国家标准 GB 45438-2025《网络安全技术 人工智能生成合成内容标识方法》，2025 年 9 月 1 日实施，标准状态见全国标准信息公共服务平台：<https://std.samr.gov.cn/gb/search/gbDetailed?id=301E0388CB75788DE06397BE0A0AE1B4>。
- 《人工智能拟人化互动服务管理暂行办法》（国家网信办等五部门令第 21 号，2026 年 7 月 15 日起施行）适用于模拟自然人人格、思维和沟通风格的持续性情感互动。该办法写明：智能客服、知识问答、工作助手、学习教育、科学研究等不涉及持续性情感互动的，不适用。漫金海的画布助手若只做创作工具，负责人仍应确认产品文案和交互没有变成该办法所说的情感陪伴。文本：<https://www.cac.gov.cn/2026-04/10/c_1777558395078289.htm>。

「大模型备案」没有单独一份与算法备案并列、且本文可以替产品勾选的通用表格。公开信息里，生成合成与具有舆论属性或社会动员能力的生成式服务，走的是上面的安全评估和算法备案（备案系统同时发布深度合成算法备案公告）。漫金海没有自己的预训练模型。负责人需要确认：调用 Agnes 或其他上游时，本站要备案的是服务与标识，还是同时要申报模型；上游已备案不能自动代替本站的义务。

第二期上线前，产品侧至少要有负责人确认过的方案：生成结果的显式标识、导出文件的显式与隐式标识、用户协议中的标识说明、违法内容的停止生成与投诉入口。第一期邀请内测若已经向他人提供生成，应同时确认这些义务是否已经开始，而不是默认等到公开注册。

### 5.3 用户协议、隐私与个人信息

注册收集邮箱，资料里有昵称。生成请求会把用户写下的剧本、提示词和参考图送到上游模型。项目和素材一旦上云，就离开用户自己的浏览器。

《生成式人工智能服务管理暂行办法》第九条、第十一条把个人信息处理、输入信息和使用记录的保护写在提供者义务里。《个人信息保护法》是这些条款所依据的法律之一（办法第一条）。协议和隐私政策至少要说明：收集哪些信息、保存多久、是否把提示词和素材发给模型服务、用户如何导出和删除、投诉入口。具体条款、保存期限和跨境传输（模型 API 若在境外）由负责人请法律顾问按实际数据流写，本文不给模板条文。

现有界面没有用户协议或隐私政策页面。`index.html` 只有一句产品描述。

### 5.4 AGPL-3.0 对网络用户提供源码

`package.json` 的 `license` 为 `AGPL-3.0-only`。`LICENSE` 是 GNU Affero General Public License 第 3 版。官方文本第 13 条：如果你修改了本程序，并且修改版支持用户通过计算机网络远程交互，则必须向这些远程用户显著提供获得该版本对应源码的机会，通过网络服务器免费提供，方式为便于复制软件的常规手段。官方文本：<https://www.gnu.org/licenses/agpl-3.0.html>。

因此，公网上跑的如果是修改过的漫金海，站点里要有明显的源码入口（例如页脚「源码」链到与线上版本一致的公开仓库或源码包）。对应源码包含构建和运行该版本所需的脚本，不包含用户项目、`.env`、`.local/model-configs.json` 和对象存储里的媒体。`npm run package:source` 的白名单已经排除这些本地密钥目录（`docs/open-source-release.md`），可以作为发布源码包的起点，但线上版本号要和包一致。

只把未修改的官方版本原样跑起来时，第 13 条的「修改版」前提是否成立，仍以许可证原文和负责人的确认行为准。本仓库已经改过并准备继续改，公开站应按「需要提供源码」准备。

AGPL 不要求把用户的作品、密钥或私有配置公开。

## 7. 分期，以及和 Agent 路线图的关系

Agent 路线图（`docs/agent-canvas-roadmap.md`）默认数据仍在浏览器：P0 的会话键是 `mjh.agentSessions.v1`，工具在浏览器执行，FastAPI 只转发模型。公开站改变的是账号、项目正文和媒体的位置。两条线可以并行设计，不能各写一套存储。

### 7.1 第一期：邀请内测

交付：

- 沿用 Supabase 邮箱登录。FastAPI 校验 JWT。未登录不能调用 `/api/chat`、图像、视频和模型配置。
- 项目库和媒体进数据库与对象存储，按 `user_id` 隔离。本机未登录模式保持现状。
- 导入：个人中心里的本机库，以及 `.mjh.json`（继续校验 `parseBackup`，结果是新副本）。
- BYOK：每用户一份加密配置。环境变量 Key 不作为公开请求的回退。
- 基本限流和视频任务队列。视频结果进对象存储，不再在一个 HTTP 响应里返回整段 MP4。
- 部署：静态前端、独立后端、HTTPS、同域或明确的 API 基址、密钥不进仓库。邀请名单或关闭公开注册。
- 页脚放 AGPL 源码链接，指向与该次部署一致的源码。

规模：存储和鉴权穿过 `projectStore`、`mediaStore`、`projectBackup`、`accountStorage` 和 `backend/app.py`、`backend/model_configs.py`。大于 Agent P0（Agent P0 不改这些持久化边界）。视频队列是其中一块独立工作，因为现在的等待发生在请求内部。

第一期不做：平台代付、积分、公开注册、完整的内容审核后台。若内测已经让受邀用户生成图片和视频，第 5 节的备案和标识是否同步开始，由负责人确认，不由「仍是内测」自动跳过。

### 7.2 第二期：公开注册

交付：

- 负责人确认适用的 ICP 备案或许可、算法备案与安全评估、生成内容显式和隐式标识、用户协议、隐私政策、投诉入口。未确认前不开放公开注册。
- 额度或计费。调用前预留，失败退回。BYOK 用户不扣平台额度。
- 监控、空项目引导、落地页、手机上的首页和项目列表。
- 违法内容的停止生成与记录，具体供应商和规则由负责人选定。本文不指定审核服务。

规模：计费和审核是新子系统。标识要接在图片 data URL 和视频结果落盘的位置（`image_data_url`、视频 worker），并覆盖 `.mjh.json` 导出。落地页和协议小于第一期的数据迁移。

### 7.3 和 Agent 三期怎么接

| Agent 路线图 | 公开站需要它配合的点 |
| --- | --- |
| P0，浏览器里的工具循环，会话写 `mjh.agentSessions.v1` | 可以先在本机做完，不阻塞。公开站第一期上线时，会话要跟项目一起按 `user_id` 存放，不能只有画布上了云、对话仍留在那一台浏览器的 localStorage。P0 设计的 FastAPI 只转发、工具仍在浏览器执行，与第一期的「密钥在服务端、画布在云端」兼容：转发必须使用当前用户的 Key。 |
| P1，确认后的生图生视频、花费守卫 | 调用现有 `generateImages` / `generateVideo`。公开站第一期若已把视频改成任务 id，P1 就要消费任务状态，而不是等待一整段 MP4 响应。花费守卫与第二期额度用同一本账。参考图若需要公网 URL，用该用户对象的短期签名 URL，不要把桶设成公开。 |
| P2，项目记忆、版本快照、队列 | 快照存云端对象或数据库，随账号走。不要做一套只存在 IndexedDB 的版本历史。 |

推荐顺序：本机 Agent P0 与公开站第一期的存储设计同时定稿，避免会话键和媒体 id 各写一次。公开注册放在合规确认和额度之后。Agent P1 的真实出图不要先于视频任务队列和对象存储。
